# OpenAPI для backend-роутов

Поддерживай документацию API в `backend/` в соответствии с реально зарегистрированными HTTP-роутами.

## Рабочий процесс

1. Найди регистрацию маршрута в `backend/internal/http/router.go` и соответствующий handler. Проверь также другие файлы backend, если роутер был вынесен или добавился новый.
2. Для каждого добавленного или изменённого API-роута актуализируй Swaggo-аннотации над handler: минимум `@Summary`, `@Tags`, подходящие `@Accept`/`@Produce`, параметры, все ожидаемые коды `@Success`/`@Failure`, `@Security BearerAuth` для защищённых маршрутов и точный `@Router` с HTTP-методом.
3. При удалении маршрута удали его аннотации вместе с неиспользуемыми схемами, если они больше не нужны. Не оставляй endpoint в сгенерированном контракте.
4. Описывай request/response через существующие именованные Go-типы. Если тип приватный, это допустимо: Swaggo запускается с `--parseInternal --parseDependency`. Для multipart-загрузок используй `formData` и явно документируй имя файла.
5. Перегенерируй контракт и Redoc одним скриптом из корня репозитория:

   ```bash
   .codex/skills/sync-backend-openapi/scripts/sync_openapi.sh
   ```

   Скрипт сам запускает Swaggo из каталога `backend/`, а затем строит `backend/docs/swagger.html` через Redoc.

6. Проверь изменения в `backend/docs/`: сгенерированные `docs.go`, `swagger.json`, `swagger.yaml` и `swagger.html` должны быть включены, если изменились. Не редактируй эти файлы вручную.
7. Проверь согласованность: сравни зарегистрированные API-роуты с `@Router`, убедись, что удалённые endpoints исчезли из `swagger.yaml`/`swagger.json`, и выполни `go test ./...` из `backend/` (либо сообщи о конкретной причине, если проверка недоступна).

## Ограничения

- Не меняй поведение handler только ради документации и не добавляй фиктивные endpoints.
- Учитывай фактические статусы и форматы ответов, включая ошибки, cookies, bearer-аутентификацию и multipart-запросы.
- Если API-роут изменён вместе с моделью или схемой, документируй только наблюдаемое HTTP-поведение; бизнес-логику не расширяй.
- После генерации проверь `git diff --check` и не включай нерелевантные файлы.
